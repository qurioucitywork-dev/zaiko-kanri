# フェーズ0 現状監査

実施日：2026-07-26

## 調査結果

- GitHubリポジトリは空で、既存コード・DB・CI・未コミット業務実装は存在しなかった。
- 添付ZIPはHTML/CSS/JavaScriptで構成された画面プロトタイプであり、永続DB・サーバー認証・同時実行制御はない。
- スクリーンショットはログイン、ダッシュボード、在庫、仕入、売上、出荷、返品、承認、購入依頼などのUI基準として利用できる。
- 確定仕様では旧プロトタイプの「バイヤー」を「作業者」に統一し、OTPは初期版に含めない。

## 再利用方針

- 配色、サイドメニュー、カード、テーブル、ステータス表示などの視覚言語をGoテンプレートへ移植する。
- 画面上の業務項目と操作導線は参考にする。
- ブラウザ内サンプルデータ、sessionStorage認証、クライアント側だけの権限制御は再利用しない。
- 業務ルール、組織境界、権限、監査、状態遷移はサーバー側で新規実装する。

## 技術方針

- Go 1.26、標準`net/http`、`html/template`を使用する。
- ローカルプレビューと自動テストはSQLiteを使用する。
- スキーマはSQLマイグレーションとして管理し、業務処理はDBトランザクションへ集約する。
- 本番DBをPostgreSQLへ切り替える際に依存箇所を限定できるよう、DBアクセスを`internal/database`へ集約する。
- 金額は後続フェーズで最小通貨単位の整数として扱う。

## 主なリスク

- 添付プロトタイプには本番相当のデータ整合性・競合制御がないため、画面上の挙動をそのまま仕様とみなさない。
- 承認金額、取置期限、為替提供元、CSV/PDF形式は未確定のため組織設定として保持する。
- 商品コード採番、仕入確定、取置、売上確定、分納は後続フェーズで競合テストが必要。
