# フェーズ6実装報告：承認ワークフロー

## 実装範囲

- 承認申請、承認、差戻し、却下、失効と判断履歴
- 作業者による売上・出荷取消を承認申請へ接続
- 設定閾値以上の売上確定を承認申請へ接続
- 管理者の通常操作は初期設定で承認不要
- 将来用の「管理者の高額売上も承認対象」設定と専用閾値
- 申請者本人による自己承認のサーバー側禁止
- 申請後に対象データが変わった案件の自動失効
- 差戻しコメントの必須化
- 承認時に保存済み操作を実行し、物理削除を行わない設計

## データ設計

`approval_requests` に申請対象、操作キー、申請者、申請時スナップショットとハッシュ、理由、実行用ペイロード、判断状態を保持します。`approval_actions` は申請から判断までの追記型履歴です。同じ対象・操作に対する未処理申請は一件に制限しています。

## 承認ルール

- 作業者の重要操作は承認待ちにします。
- 作業者の売上確定は `approval.sales_threshold_jpy` が設定済みで、円換算額が閾値以上の場合に承認待ちにします。
- 管理者は初期状態では即時実行します。
- `approval.admin_high_value_enabled` を有効にすると、管理者も専用閾値以上の売上で別管理者の承認が必要です。
- 管理者であっても自分の申請は承認、差戻し、却下できません。
- 承認時の対象データが申請時スナップショットと一致しない場合、案件を失効させて実行しません。

## 受入確認

| ID | 確認内容 | 自動テスト |
|---|---|---|
| AT-501 | 作業者の重要操作が承認待ち | Webルート・DBテスト |
| AT-502 | 閾値以上の売上が承認待ち | DBテスト |
| AT-503 | 作業者の自己承認を拒否 | DBテスト |
| AT-504 | 管理者の自己承認も拒否 | DBテスト |
| AT-505 | 差戻しコメント必須 | DB・Webハンドラ |
| AT-506 | 対象変更後の承認を失効 | DBテスト |
| AT-507 | 初期設定の管理者は承認不要 | DBテスト |
| AT-508 | 管理者高額モードは別承認 | DBテスト |

ローカル開発環境では、承認画面をすぐ確認できるように作業者からの出荷取消申請を一件だけ自動生成します。
