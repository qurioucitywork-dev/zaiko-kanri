# フェーズ2 仕入・商品・在庫

完了日：2026-07-26

## 完了内容

- 仕入先マスター
- 仕入伝票・複数明細・下書き・確定
- 確定時の明細数量分の商品生成
- 同一組織・仕入日単位の商品コード排他採番
- 確定再送時の二重生成防止
- 単品登録時の簡易仕入伝票自動生成
- SKU重複許可
- シリアル番号重複候補の比較と理由付き続行
- 仕入中から在庫中への検品状態遷移
- 在庫イベント履歴
- 在庫一覧、検索、状態フィルタ、商品詳細
- 商品画像登録と組織スコープ付き表示
- 重要操作の監査ログ

## 商品コード

形式は`YYYYMMDDNNN`です。`product_code_sequences`を同一DBトランザクション内で更新し、取消後も番号を戻しません。日次999件へ到達した場合は商品・簡易仕入伝票を作らず、明確な業務エラーを返します。

## 状態遷移

```text
仕入伝票：下書き → 確定
生成商品：仕入中 → 在庫中
単品登録：在庫中
```

確定済み伝票の修正・取消、在庫状態の強制変更は承認フローが必要なため、フェーズ6で画面操作を接続します。DBサービスには取消時も商品コードを再利用しない処理を用意しています。

## 画像

- JPEG、PNG、WebP
- 1ファイル8MB以下
- 1商品10枚まで
- 保存パスは組織・商品単位
- 画像取得時にも認証、権限、組織境界を検証

## 自動テスト

- 仕入数量分の商品生成
- 生成直後の状態が「仕入中」
- 同時確定時の商品コード一意性
- 確定再送の冪等性
- 単品登録と簡易仕入伝票
- SKU重複許可
- シリアル重複理由の必須化
- 重複続行履歴
- 取消後の番号非再利用
- 日次1000件目の業務エラー
- 組織スコープ
