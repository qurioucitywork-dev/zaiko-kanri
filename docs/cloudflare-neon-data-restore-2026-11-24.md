# Cloudflare・Neon 登録済みデータ移行結果（2026-11-24）

## 移行結果

Cloudflare の検証アプリを、登録済みの会社情報・マスタ・商品・伝票・画像を復元した Neon データベースへ切り替えました。

- 検証 URL: https://qurioucity-zaiko-test.qurioucitywork.workers.dev
- 復元先: 元の `neondb` とは別の `zaiko_restored_20261124`。
- 最終 Worker バージョン: `a658d714-a366-4332-a043-74b76f3c6879`。
- 移行元: **2026年10月15日21:40（日本時間）に取得されたバックアップ**。それ以降の変更を含むことは保証しません。
- 元の Docker データ、バックアップ、画像ファイル、最初に作成した Neon `neondb` は保持しています。

## データの照合

復元元のバックアップを、ホストへポート公開しない専用 PostgreSQL 18 に復元しました。そのコピーで認証情報の更新と最新マイグレーションを実施し、専用 Neon DB へ復元しています。

| 確認対象 | 結果 |
| --- | --- |
| 全テーブル | **80 / 80 テーブルで行数と全行内容のハッシュが完全一致** |
| 外部キー | 未検証の外部キー制約 0 件 |
| 元から存在した業務データ | 全テーブルの件数と、全数値列の合計が移行準備の前後で一致 |
| 商品 | DB 60 件、通常一覧 59 件 |
| 仕入伝票 | DB 10 件、通常一覧 9 件 |
| 仕入明細 | 47 行 |
| 売上伝票・明細 | 15 伝票・25 明細。売上 API は調整伝票 4 件を含む 19 件 |
| 出荷伝票・明細 | 17 伝票・27 明細 |
| 返品伝票・明細 | 14 伝票・20 明細 |
| 委託伝票・明細 | 5 伝票・14 明細 |
| ユーザー | 6 件。ID、役割、有効・無効状態、業務上の関連付けを維持 |

全行照合は、JSON に変換した各行を固定の並び順で連結した MD5 と件数を、アプリ切替前に比較しています。時刻表現は UTC に統一しています。金額、個別行、認証情報、具体的なハッシュ値を公開資料には含めず、検証記録は Git 対象外のローカル領域に保管しています。

業務金額の確認には、仕入明細の円換算額、売上明細の円換算額、出荷明細の円換算売価、原価調整の元原価・配賦原価等を含めています。認証関連の予定した変更以外に、件数・数値合計の変化はありませんでした。

### DB 件数と画面件数の差

商品 60 件のうち 1 件には削除日時が設定されています。既存の `Products()` は `deleted_at IS NULL` を条件としているため、通常一覧は 59 件です。

仕入伝票 10 件のうち 1 件は `cancelled` です。既存の `PurchaseSlipsPage()` は取り消し済み伝票を通常一覧から除外するため、通常一覧は 9 件です。

この差は移行漏れではなく、既存の検索条件によるものです。削除・取り消しの履歴も DB に保持しています。

## 画像・保存済み PDF

- 商品画像 **16 件**、保存済み PDF **12 件**、合計 **28 件・12,466,417 バイト**。
- 元 DB の保存キー・SHA-256・サイズと、元の全ファイルが一致。参照のない余分なファイルは 0 件。
- 同じ保存キーで非公開 R2 にアップロードし、全件を再取得して SHA-256・サイズ・Content-Type を確認。
- 切替後に通常のログイン済みアプリ API 経由でも 28 件すべて取得し、元ファイルとハッシュが一致。
- 商品画像と保存済み PDF の DB 参照を維持し、保存先の種別をクラウド用に変更しています。

## アカウントと認証情報

旧環境のパスワードはクラウドへ持ち込みません。6 アカウントすべてのパスワードを新しいものに更新し、旧セッション、ログイン CSRF トークン、パスワード再設定トークン、管理者アクセスコードを引き継がないよう処理しました。

管理者はクラウドで新規発行済みのパスワードを使用し、担当者・ゲストはアカウントごとの新しいパスワードです。管理者 1 件、担当者 3 件、ゲスト 2 件の **全 6 件でログイン成功**を確認しました。

新しい認証情報は、アクセス権限を制限したローカルファイル `.runtime/recovered-accounts.json` に保管しています。パスワード、接続文字列、DB バックアップ、検証ログは GitHub に含めません。

## 公開アプリでの確認

ログイン後の会社表示が復元元と一致することを確認しました。商品、各種マスタ、取引先、ユーザー、仕入、売上、出荷、返品、保存済み伝票、ダッシュボード等の **14 API が HTTP 200** でした。

マスタの取得件数はブランド 10、素材 43、付属品 35、ベルト素材 14。取引先 12 件、ユーザー 6 件も確認しています。

DB の接続先変更時は `APP_INSTANCE_NAME` を変更し、復元 DB を使用する新しいコンテナで起動しました。ヘルスチェックだけでなく、ログイン後の会社情報と業務件数で切替を確認しています。旧コンテナは公開入口と定期処理の接続先から外しています。

## 残る実務テスト

データ復元と照合、読み取り API、ログイン、既存ファイル取得は確認済みです。一方、複数人の同時操作、仕入から返品・原価調整までの全登録操作、帳票の新規生成、障害からの復旧等は引き続き実務テストで確認します。

既存の追加 PostgreSQL 結合テストには未解決のフィクスチャ問題等があります。[初回検証記録](cloudflare-neon-verification-2026-11-24.md)の結果を参照してください。社内回線・VPN・ゲスト別の Cloudflare Access 設定も、本番運用条件の確定後に追加する項目です。
